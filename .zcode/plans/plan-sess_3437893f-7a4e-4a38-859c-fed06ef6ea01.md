# Kero 语音输入优化方案（对齐千问体验）

## 目标体验

按住 Alt → 胶囊以灵动岛式动效展开成语音面板（真实波形 + 实时转写文字），同时文字实时打入目标应用输入框；松开 Alt → 面板出现"润色中"扫光动画 → 润色完成原位替换、面板丝滑收回。出错时面板内提供重试/复制/取消，Esc 可随时取消。

## 现状诊断（为什么"难用 + UI 不满意"）

1. **默认引擎弱**：默认 `dictationMode: "native"`（Capsule.tsx:152）= WebView2 里的 Edge 在线识别，效果差不可控；且默认 `aiDictationPolish: false`（Capsule.tsx:153），润色默认关闭。
2. **协议错配（关键）**：现有流式实现是旧 `run-task/finish-task` 双工协议（app.rs:1972-2113，只适配 fun-asr-realtime/paraformer 类模型）；而 **Qwen3-ASR-Flash-Realtime 用的是 OpenAI-realtime 风格的新协议**（`wss://…/api-ws/v1/realtime?model=…`，`session.update`/`input_audio_buffer.append`/server_vad 断句）。配置 qwen3-asr-flash-realtime 大概率直接失败——这就是"千问聪明 100 倍、Kero 不行"的根源。
3. **多句丢失 bug**：旧协议每个事件只含"当前句"，前端覆盖式 `realtimeDictationText.current = transcript`（Capsule.tsx:1509）并整段替换，说多句时前面的句子会被吞掉。
4. **录音期间零反馈**：AI 模式只有状态小字；`.voice-wave.is-processing` 的 CSS 动画（styles.css:304）覆盖了真实能量条（styles.css 内联 scaleY 被抢占），波形是假的，转写文字看不到。
5. **采集老旧**：废弃的 ScriptProcessorNode，PCM 每 ~128ms base64 走一次 IPC（Capsule.tsx:1237-1264）。
6. **失败处理差**：错误挤在 10px 不可换行小字里省略掉，无重试；插入失败把文本塞进聊天草稿（draft 过载，Enter 会误发聊天，Capsule.tsx:913/1576）。
7. `warm_dictation_service` 预热的是聊天 LLM 而非 ASR（app.rs:4915）。

## Phase 1 识别链路升级（src-tauri/src/app.rs + Capsule.tsx 采集）

1. **新增 Qwen3-ASR-Flash-Realtime 协议适配**（按 [实时语音识别官方文档](https://help.aliyun.com/zh/model-studio/real-time-speech-recognition-user-guide) 实现时核对字段）：
   - 连接 `wss://dashscope.aliyuncs.com/api-ws/v1/realtime?model=qwen3-asr-flash-realtime`，头 `Authorization: Bearer` + `OpenAI-Beta: realtime=v1`
   - `session.update`：`input_audio_transcription: {language: "zh"}`；`turn_detection` 用 server_vad（silence ~500ms），边说边收 partial（`text`+`stash`）和每轮 `completed` 终稿
   - 音频以 `input_audio_buffer.append`（base64 JSON 事件）发送，16kHz PCM16 单声道
   - Alt 松开：`session.finish` → 等 `session.finished`
2. **会话累积全量转写**：Rust 会话保存已完成句 + 当前 partial，`kero:realtime-dictation` 事件 payload 增加 `fullText`（保留 `text` 兼容），修复多句覆盖 bug。旧协议（streaming/fun-asr-realtime）同样累积。
3. **协议自动选择**：model 含 `realtime` → 新协议；含 `streaming` 或 fun-asr-realtime/paraformer → 保留旧协议（放宽 app.rs:1974 的 gate）。
4. **降级链**：前端在流式启动同时并行 MediaRecorder 录整段，流式失败/中断且无结果 → 自动走 `transcribe_dictation_audio` 整段转写（批量路径已支持 qwen3-asr-* / qwen-audio-3.0-asr-flash / OpenAI 兼容接口）。
5. **启动提速**：getUserMedia 与 `start_realtime_dictation` 并行发起；`warm_dictation_service` 改为预热 DashScope 域名/连接。
6. **采集升级**：AudioWorklet（源码内联 Blob URL，无需 public 目录）替换 ScriptProcessorNode，~100ms 一批。

## Phase 2 灵动岛语音面板（Capsule.tsx + styles.css）

1. **状态机**：`idle → listening → finishing → polishing → inserting → idle / error`，文案集中到一张状态表，替代散落的 `setDictationStatus` 字符串。
2. **布局**：听写时主窗口 420×72 展开至约 420×150（经 `set_main_size`）：第一行保持胶囊行（mic 圆盘 + **真实能量**波形 + 状态），下方展开转写区——玻璃面板内 14px 文字流式增长、自动滚到底、底部渐隐遮罩，显示累积 `fullText`。
3. **动效**：
   - 复用 `set_main_size` 的 easeOutBack 窗口动画（app.rs:8163-8186）；窗口贴近屏幕底部时改为**向上展开**（前端用 `currentMonitor()` 算工作区，传 `restoreY` 固定底边）
   - 转写区高度/透明度 CSS transition，文字 fade-slide-in
   - 修复 CSS 优先级让录音时波形跟随真实能量；润色态改为转写文字上的 shimmer 扫光（不再是假波形）
4. **错误态**：面板内深色错误条 + 重试 / 复制 / 取消按钮（遵守黑白蓝设计语言），不再用状态小字。
5. 完成或取消后收回 72px；托盘唤起的听写结束后自动隐藏（沿用 `hideAfterTrayDictation`）。

## Phase 3 松开后的润色与上屏（Capsule.tsx + app.rs 钩子）

1. 松开 → `finishing` → 拿到 `fullText` → `optimize_dictation`（词表/记忆/安全门保留）→ `replace_realtime_dictation_text` 原位替换 → 收起；润色失败/超时自动回退原始转写（现状已兜底，保留）。
2. 插入失败不再写入聊天 draft：面板保留文字并提供 重试插入 / 复制 按钮；顺手修复 draft 过载问题。
3. **Esc 取消**：键盘钩子在听写激活时把 Esc 转成新事件 `kero:shortcut-dictation-cancel` → 前端把已打入的 span 替换为空、结束会话、收起面板。

## Phase 4 默认值、设置与清理（SettingsWindow.tsx + styles.css）

1. 已配置 ASR key 时默认 `dictationMode: "ai"`、`aiDictationPolish: true`；未配置走 native 并在设置里给引导提示。
2. SettingsWindow AI 听写区：模型占位符/推荐文案改为 `qwen3-asr-flash-realtime`，说明流式模型命名规则。
3. CSS 清理：删除 dark/pearl 两层遗留听写规则，只保留 final 层，防止继续叠 dead rules。

## 验证

- `cargo check`、`npm run build` 通过
- 手动场景：记事本/微信按住 Alt 说 2-3 句 → 实时上屏且面板转写一致（多句不丢）；松开润色原位替换；Esc 取消清空；错误 key/断网走降级链且面板有重试；托盘唤起听写结束自动隐藏；窗口贴底时向上展开。

## 风险

- Qwen3-Realtime 协议细节（事件名/字段/热词 context 参数）以官方文档为准，实现时需联调验证。
- 旧协议回放兜底 `transcribe_realtime_dictation_audio`（app.rs:2147）只适配旧协议，降级链改为前端 MediaRecorder 整段后可不再依赖它。

实施顺序：Phase 1 → 2 → 3 → 4（1、2 是核心，可分别验收）。
